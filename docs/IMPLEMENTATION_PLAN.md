## 1. Соглашение о порядке работы

Работа ведётся по функциям и небольшим связанным блокам.

1. Пользователь называет функцию или блок, который нужно реализовать.
2. Перед изменением проверяется текущая архитектура, зависимости и интерфейсы.
3. Готовится реализация с пояснениями назначения, входов, выходов, единиц и поведения при ошибках.
4. Отдельно перечисляются проверки: штатные случаи, границы и ошибки.
5. Пользователь проверяет результат и либо одобряет, либо возвращает на исправление.
6. Только после одобрения блока начинается следующий зависимый блок.
7. Реализуются только функции, уже перечисленные в утверждённой архитектуре и плане. Новые функции и требования по ходу работы не добавляются.
8. Допускается только минимальный код, необходимый для работы выбранной функции и её связи с уже реализованными частями.
9. Не добавлять лишние уровни абстракции, универсальные механизмы, дополнительные возможности и рефакторинг «заодно». Если без изменения списка функций задача не решается, сначала отдельно объяснить причину и согласовать изменение плана.

Не объединять в один шаг драйвер IMU, оценку ориентации и регулятор. Не менять сразу несколько коэффициентов или уровней системы в ходе эксперимента. Не заявлять, что код собран или проверен на железе, если соответствующая проверка действительно не выполнена.

## 5. Этап 3. Калибровка и оценка ориентации

Функции:

1. `detectStationary()` — [x] реализована; проверяет последовательное окно IMU без встроенных порогов.
2. `calibrateGyroBias()` — [x] вычисляет средний gyro bias по окну, прошедшему `detectStationary()`; выход при отказе не меняется.
3. `validateCalibration()` — [x] проверяет максимальное отклонение каждого измерения gyro от рассчитанного bias; порог передаётся явно.
4. `resetCalibration()` — [x] обнуляет переданный gyro bias и сбрасывает caller-owned признак валидности; окно образцов не меняет.
5. `initializeEstimator()` — [x] задаёт единичный нейтральный кватернион, обнуляет метаданные образца и оставляет оценку невалидной;
6. `updateOrientation()` — [x] интегрирует gyro после вычитания bias по фактическому интервалу, проверяет временные метки и sequence; алгоритм коррекции по accel/magnetometer не добавлен;
7. `validateOrientation()` — [x] проверяет valid flag, конечность quaternion и отклонение нормы от единицы с явно переданным допуском; не исправляет оценку;
8. `publishOrientationTelemetry()` — [x] выводит одну CSV-строку: timestamp, sequence, valid и четыре компоненты quaternion с точностью шесть знаков; невалидная оценка также выводится с `valid=0`.

`detectStationary()` готова: критерии передаются через `StationaryCriteria`, используются валидные accel/gyro, величина gyro, модуль ускорения относительно стандартной гравитации и вариация вектора ускорения внутри окна. Проверяются свежесть последнего образца, интервалы и порядок timestamp/sequence с корректной обработкой rollover.

`calibrateGyroBias()` готова: получает уже собранное окно, повторно подтверждает неподвижность через `detectStationary()` и вычисляет среднее значение угловой скорости по X/Y/Z в рад/с. Функция не читает датчик и не хранит состояние; при отказе выходной вектор не меняется. Проверка разброса остаётся отдельной обязанностью `validateCalibration()`.
`validateCalibration()` готова: повторно проверяет окно через `detectStationary()`, валидность bias и порога, а затем сравнивает каждое измерение gyro с bias по евклидову расстоянию. Допустимый предел включительный и задаётся вызывающим кодом. Даже единичный выброс за пределом отклоняет калибровку; входные данные не меняются.
`resetCalibration()` готова: устанавливает переданный gyro bias в ноль и переводит caller-owned `calibrationValid` в `false`. Повторный вызов безопасен; функция не очищает буфер образцов, не обращается к IMU и не хранит глобальное состояние.
`initializeEstimator()` готова: полностью перезаписывает `OrientationEstimate`, задаёт единичный кватернион scalar-first `(w, x, y, z) = (1, 0, 0, 0)`, обнуляет `timestampUs` и `sequence`, устанавливает `valid = false`. Это нейтральное начальное состояние, а не измеренная ориентация. Фильтр не выбран; функция не обращается к IMU и не вычисляет ориентацию.
`updateOrientation()` готова: первый валидный gyro sample фиксирует временную/sequence-привязку и начинает относительный отсчёт без придуманного вращения. Далее интегрируется точный quaternion increment для постоянной угловой скорости между образцами после вычитания переданного gyro bias. Используются unsigned-разности timestamp/sequence с обработкой rollover; повторные, обратные, неоднозначные и слишком большие интервалы отклоняются. При отказе `OrientationEstimate` не меняется. Это gyro-only относительная оценка: дрейф сохраняется, коррекция по акселерометру и магнитометру не реализована.
`validateOrientation()` готова: проверяет `valid`, конечность четырёх компонент quaternion, ненулевую конечную норму и абсолютное отклонение нормы от единицы. Допуск конечный, неотрицательный и передаётся вызывающим кодом; равенство границе принимается. Функция ничего не нормирует и не меняет исходную оценку. Timestamp и sequence не служат критерием валидности, поскольку ноль допустим при старте и rollover.
`publishOrientationTelemetry()` готова: выводит переданный `OrientationEstimate` одной CSV-строкой из семи полей в порядке `timestamp_us,sequence,valid,quaternion_w,quaternion_x,quaternion_y,quaternion_z`. Компоненты quaternion выводятся с шестью знаками после запятой. Невалидная оценка также выводится с `valid=0`; остальные сохранённые поля не переписываются. Функция не читает IMU, не проверяет и не нормирует quaternion, не меняет оценку; частоту вызова определяет внешний код.

Начальный режим: сначала регистрируем и проверяем сырые gyro/accel/magnetometer данные. Затем сравниваем DMP ICM-20948 (6-/9-осевой quaternion), простой комплементарный фильтр и host-side Mahony. Комплементарный фильтр служит прозрачной базой для наклона; DMP и Mahony оцениваем отдельно. Магнитометр не влияет на обратную связь, пока не проверены калибровка и магнитные помехи от MG90S.

Проверки:

- неподвижный датчик не создаёт заметного самопроизвольного вращения сверх измеренного шума/дрейфа;
- калибровка отклоняется при движении;
- поворот на известный угол меняет оценку в правильном направлении;
- нормировка кватерниона сохраняется;
- некорректный `dt`, NaN/Inf и потеря новых данных не портят состояние фильтра;
- результат не зависит от того, как часто Serial Monitor запрашивает вывод.

Отдельно решить вопрос магнитометра. Если управляемая ось совпадает с yaw/вертикальной осью, нельзя объявлять долговременную абсолютную стабилизацию курса достигнутой без надёжного внешнего ориентира.

## 6. Этап 4. Координаты, опора и одна управляемая ось

Функции:

1. `validateMountingConfig()`;
2. `transformImuToPlatform()` — [x] преобразует входной вектор в координаты платформы тремя скалярными произведениями с её осями, заданными в координатах IMU; единицы измерения сохраняются.
3. `captureReferenceOrientation()` — [x] сохраняет прошедший проверку кватернион текущей оценки; повторный захват заменяет прежнюю опору, при отказе она не меняется.
4. `computeRelativeOrientation()` — [x] вычисляет `inverse(reference) * current`, проверяет обе ориентации и нормирует результат; при ошибке выход не меняется.
5. `projectErrorOnControlAxis()` — [x] извлекает signed twist error по заранее нормированной оси IMU и возвращает кратчайший угол в радианах; проверяет норму quaternion и длину оси, при неоднозначном 180° swing отказывает без изменения выхода.
6. `projectGyroRateOnControlAxis()` — [x] вычитает явно переданный gyro bias из каждой компоненты угловой скорости IMU и проецирует результат на ту же предварительно нормированную ось; возвращает рад/с, при ошибке выход не меняется.

Управление по-прежнему отключено. На этом этапе устанавливается соответствие IMU ↔ платформа ↔ мировая система координат.

`transformImuToPlatform()` готова: принимает конечный вектор в координатах IMU и предварительно проверенный `MountingConfig`, вычисляет компоненты платформенного вектора скалярными произведениями с тремя осями платформы. Частота вызова не добавляет повторной проверки монтажа; она должна быть подтверждена через `validateMountingConfig()` до использования. Единицы вектора сохраняются. При NaN/Inf входа или результата, который не представим в `float`, возвращается `false`, выход не меняется. Входной вектор и конфигурация не изменяются.

`captureReferenceOrientation()` готова: принимает `OrientationEstimate` и явно заданный `maximumNormDeviation`, проверяет оценку существующей `validateOrientation()`, затем копирует кватернион в `ReferenceOrientation` и устанавливает `valid = true`. Повторный захват заменяет предыдущую опору. При невалидной оценке, некорректном допуске или нарушенной норме функция возвращает `false`, не меняя прежнюю опору. Исходная оценка не изменяется; quaternion не нормируется, не инвертируется и не преобразуется. Момент захвата задаёт внешний код; автоматического захвата при старте нет.

`computeRelativeOrientation()` готова: валидирует текущую оценку и сохранённую опору существующей `validateOrientation()` с явно переданным допуском. Вычисляет `q_relative = inverse(q_reference) * q_current`; для обратного кватерниона используется сопряжение, делённое на квадрат нормы опоры, поэтому допускается погрешность нормы в пределах допуска. Результат нормируется до единичной длины. При ошибке обе входные структуры и выходной кватернион остаются без изменений. Свежесть измерений и выбор управляемой оси остаются ответственностью вызывающих функций.

`projectErrorOnControlAxis()` готова: принимает относительный quaternion `inverse(reference) * current` и заранее нормированную `AxisConfig.axisInSensorFrame`. Извлекает twist-компоненту вокруг этой оси проекцией векторной части quaternion на ось и вычисляет `2 * atan2(projectedVector, w)`. Перед расчётом знак quaternion выбирается однозначно, в том числе на границе 180°, поэтому эквивалентные `q` и `-q` дают одинаковую ошибку. Результат находится в диапазоне кратчайшего signed-угла `[-π, +π]`; при 180° swing без компоненты вращения вокруг управляемой оси функция отказывает. Допуск нормы quaternion и длины оси передаётся вызывающим кодом; при ошибке выход не меняется. Это вычисление ошибки, а не команда серво.

Host-проверки `projectErrorOnControlAxis()` пройдены с GCC C++11 и флагами `-Wall -Wextra -Wpedantic -Werror`, затем повторены с AddressSanitizer и UndefinedBehaviorSanitizer. Arduino-сборка и испытание на физическом IMU не выполнялись.

`projectGyroRateOnControlAxis()` готова: принимает измеренную угловую скорость гироскопа и `gyroBiasRadPerSec` в координатах IMU, вычитает bias отдельно из X/Y/Z и скалярно проецирует скорректированный вектор на `AxisConfig.axisInSensorFrame`. Ось должна быть заранее нормирована через `normalizeAxisConfig()`; функция проверяет конечность компонентов и длину оси в пределах явно переданного `maximumAxisNormDeviation`. Промежуточная математика выполняется в `double`, результат возвращается в рад/с. NaN/Inf, некорректная ось, допуск или значение вне диапазона `float` отклоняются без изменения выхода. Функция не читает IMU, не проверяет свежесть образца и валидность калибровки, не хранит состояние и не управляет серво: вызывающий код обязан передавать только свежие данные и валидный bias.

Host-проверки `projectGyroRateOnControlAxis()` пройдены с GCC C++11 и флагами `-Wall -Wextra -Wpedantic -Werror`, затем повторены с AddressSanitizer и UndefinedBehaviorSanitizer. Arduino-сборка и испытание на физическом IMU не выполнялись.

Проверки:

- известные повороты механики дают ожидаемый знак;
- поворот на полный круг обрабатывается без скачка ошибки на границе ±π;
- смена начальной опоры меняет ноль ошибки предсказуемо;
- движение по неуправляемой оси не подменяет ошибку управляемой оси;
- преобразования проверяются независимыми математическими тестами.

## 7. Этап 5. Драйвер MG90S в безопасном ручном режиме

Функции:

1. `beginServo()` — [x] проверяет параметры, настраивает период PWM и подключает Servo к переданному GPIO с переданными пределами; не задаёт положение и не отправляет импульс движения.
2. `setServoTarget()` — [x] сохраняет исходный запрос в переданное вызывающим кодом состояние без ограничения импульса и без отправки PWM.
3. `limitServoPulse()` — [x] ограничивает исходный запрос переданными min/max в пределах API ESP32Servo; при некорректных границах возвращает отказ без изменения результата.
4. `limitServoSlewRate()` — [x] ограничивает скорость изменения импульса по фактическому интервалу между отправками; не хранит состояние и не выдаёт PWM.
5. `writeServoPulse()` — [x] отправляет только подключённой серве уже ограниченный импульс в переданных безопасных пределах; при ошибке PWM не вызывается.
6. `disableServoOutput()` — [x] прекращает выдачу PWM через `detach()`; повторный вызов для отключённого объекта допустим, автоматическое перемещение не выполняется.

Сначала серва проверяется отдельно от автоматического регулятора. Команды выдаются только в узком предварительно проверенном диапазоне, с механически безопасной установкой платформы.

Измерить:

- реальный центр;
- безопасные минимальный и максимальный импульсы;
- направление движения;
- примерный ход вала на заданную команду;
- задержку реакции и скорость под нагрузкой;
- люфт и минимальный эффективный шаг.

Старые значения PWM можно использовать как ориентиры для планирования измерения, но не как разрешение на движение.



`beginServo()` готова: отклоняет уже подключённый объект, отрицательный GPIO, неположительную частоту и пределы импульса вне диапазона ESP32Servo 500–2500 мкс или с `minimumPulseUs >= maximumPulseUs`. Частота и границы передаются вызывающим кодом; GPIO не зашит, механические безопасные пределы не предполагаются. Функция вызывает `setPeriodHertz()` и `attach()`, затем проверяет `attached()`, поскольку номер канала 0 может быть допустимым. Начальную позицию и PWM-команду не отправляет. `attached()` отражает только состояние объекта библиотеки, а не измеренное наличие сигнала на GPIO; версия API проверена на ESP32Servo 3.2.1, но точная библиотека и плата должны быть закреплены перед target-сборкой.

`setServoTarget()` готова: копирует `requestedPulseUs` в переданное вызывающим кодом `pendingTargetPulseUs` без ограничения диапазона и без обращения к объекту `Servo`. Исходный запрос остаётся доступен следующему этапу `limitServoPulse()`. Значение нельзя отправлять напрямую в `writeServoPulse()` в обход ограничителей. Функция не формирует PWM и не хранит глобальное состояние.

`limitServoPulse()` готова: принимает исходный `requestedPulseUs` и переданные вызывающим кодом `minimumPulseUs`/`maximumPulseUs`. Границы проверяются на порядок и соответствие диапазону API ESP32Servo (`MIN_PULSE_WIDTH`–`MAX_PULSE_WIDTH`); затем запрос при необходимости прижимается к ближайшей границе. При неверных границах возвращается `false`, выходное значение остаётся неизменным. Границы API не подтверждают механическую безопасность конкретного MG90S — реальные min/max остаются ответственностью конфигурации после стендовой проверки. Функция не обращается к `Servo` и не выдаёт PWM.

`limitServoSlewRate()` готова: принимает последнюю успешно отправленную команду `currentPulseUs`, уже ограниченную целевую команду `targetPulseUs`, максимально допустимую скорость в мкс/с и время с момента предыдущей успешной отправки в мкс. По произведению скорости на время определяет разрешённый шаг; дробная часть округляется вниз, чтобы не превысить заданную скорость. Перемещение выполняется в сторону цели и не перескакивает через неё. Нулевая скорость или нулевой интервал не меняют текущую команду. Отрицательная или неконечная скорость отклоняется без изменения выхода. Функция не хранит время/состояние и не отправляет PWM; вызывающий код обновляет `currentPulseUs` и момент последней отправки только после успешного `writeServoPulse()`.

`writeServoPulse()` готова: перед отправкой проверяет `servo.attached()`, порядок min/max, соответствие границ диапазону API ESP32Servo и нахождение `pulseUs` внутри переданного механически безопасного диапазона. При любой ошибке возвращает `false` и не вызывает `writeMicroseconds()`. При успехе передаёт импульс без преобразования или дополнительного ограничения и возвращает `true`. Поскольку библиотечный `writeMicroseconds()` не сообщает статус физического сигнала, `true` подтверждает только вызов метода подключённого объекта. Последнее отправленное значение и время отправки остаются состоянием вызывающего кода; оно обновляется только после успешного возврата.

`disableServoOutput()` готова: если Servo подключён, вызывает `detach()`, затем проверяет `attached()` и возвращает `true` только если объект библиотеки сообщает об отключении. Отключение PWM может снять удерживающий момент MG90S; это не гарантирует механическую фиксацию платформы и не заменяет отдельное решение по безопасному состоянию механики.

- время установления;
- перерегулирование;
- амплитуда остаточных колебаний;
- диапазон PWM и частота насыщения;
- число пропусков, тайм-аутов и ошибок датчика.

Сначала проверяем неподвижную платформу, затем ручные небольшие возмущения, затем повторяемые тесты с одинаковыми параметрами. Не меняем одновременно фильтр, коэффициенты, dead-zone и ограничения привода.

## 13. Условия готовности первой версии

Первая версия считается пригодной для дальнейших испытаний, когда:

- связь с IMU стабильно работает;
- оценка ориентации проходит проверочные повороты;
- физическая ось и знаки документированы;
- безопасный диапазон MG90S измерен;
- замкнутый контур имеет подтверждённый отрицательный знак обратной связи;
- dead-zone не вызывает дребезга и не мешает демпфированию;
- потеря свежих данных отключает автоматическое управление;
- диагностика позволяет восстановить ход эксперимента;
- повторные испытания дают сопоставимые результаты.

Успешная компиляция, успешное чтение IMU и реальная стабилизация — три разных уровня готовности. Их нельзя смешивать в отчётах.

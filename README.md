# Gyrostab

Проект одноосевого гиростабилизатора на ESP32 Nano, ICM-20948 и сервоприводе MG90S.

## Текущая задача

Разработка новой прошивки с нуля. Старый экспериментальный скетч сохранён в `archive/gyro.cpp` только как исторический материал. Он не является основой новой реализации и не должен переноситься в неё механически.

## Аппаратная конфигурация

| Узел | Принято / известно |
|---|---|
| Контроллер | ESP32 Nano |
| Инерциальный модуль | GY-IMU20948v2 на ICM-20948 |
| Интерфейс IMU | SPI |
| SPI SCK / MISO / MOSI / CS | GPIO 18 / 19 / 23 / 5 |
| Сервопривод | MG90S |
| Управление сервоприводом | PWM, GPIO 25, библиотека ESP32Servo |
| Предполагаемая частота серво-сигнала | 50 Гц, требует подтверждения на выбранной библиотеке и экземпляре |
| Положение IMU | На подвижной платформе |

Физическая ось стабилизации, ориентация осей IMU относительно платформы, безопасный диапазон импульсов и фактическая динамика сервы пока не считаются окончательно подтверждёнными. Исторические значения из старого скетча не являются рабочими настройками новой прошивки.

## Среда разработки

Используем Arduino IDE и обычный Arduino Sketch: основной файл `gyrostab.ino`, отдельные модули `.h/.cpp` — в `src/`. PlatformIO не является частью принятого рабочего процесса.

## Главные инженерные принципы

1. Сначала проверяем измерения и системы координат, затем включаем автоматическое управление.
2. Контроллер использует только свежие, проверенные данные IMU.
3. Целевое положение, оценка ориентации, ошибка и PWM-команда — разные величины.
4. IMU установлен на подвижной платформе; преобразования координат должны учитывать это.
5. MG90S — позиционный сервопривод. Мы управляем его целевой позицией, а не напрямую моментом двигателя.
6. В первой версии используем P-D-подобное управление без интегральной составляющей; коэффициенты определяются экспериментально.
7. Dead-zone реализуется с гистерезисом и не должна отключать необходимое демпфирование по угловой скорости.
8. Магнитометр включается в оценку курса только после проверки магнитных помех от сервы и механики.
9. Любые пределы движения и аварийное состояние определяются с учётом реальной механики; автоматическое движение в центр при ошибке не предполагается без проверки безопасности.

## Порядок совместной работы

Работа ведётся в `main`, без создания новых веток. Пользователь выбирает конкретную функцию или небольшой связанный блок. Для него готовятся реализация, пояснение логики, перечень проверок и известные ограничения. После рассмотрения пользователь одобряет решение либо отправляет его на исправление; к следующему блоку переходим после одобрения предыдущего.

До появления подтверждённой спецификации не добавлять в прошивку предположения о физической оси, знаках, диапазонах PWM или частотах. Не объявлять аппаратные испытания выполненными, если они не проводились.
